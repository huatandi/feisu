R25：把识别搬到后台线程（这次是结构性修复，不是调参）

为什么卡：
识别（ZXing）一直跑在主线程上，单次解码要 30–50ms，硬档甚至 80–170ms。
主线程被占住的这段时间里，相机预览画不出新帧 —— 所以移动手机时画面会“跳帧/延迟”。

怎么改的：
- 新增 js/decode-worker.js：一个后台线程，里面加载同一份 ZXing。
- 主线程只做两件事：把这块像素画出来(getImageData)、把像素转交给后台线程（几十毫秒 → 几毫秒）。
- 后台算完把结果送回；主线程下一轮轮询时直接取用。
- 识别能力完全不变：同样的 ZXing、同样的码制、同样的硬档（全格式 + TRY_HARDER）。

安全兜底（重要）：
- 浏览器不支持 Worker → 自动退回原来的主线程解码，功能不受影响。
- Worker 出错或连续 30 次解不出 → 自动关闭 worker，退回主线程。
- 1.5 秒没回应答 → 视为超时，重新发包。

诊断新增一格里能看到它有没有生效：
"worker": { "frames": N, "hits": M, "on": true }
- on: true 表示 worker 已启用
- frames 应持续增长；hits 是成功取回结果的次数

如果 worker.on 是 false：说明这台设备/这个版本没起 worker，功能仍是好的（走主线程），
