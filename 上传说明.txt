FEISU v5.1.23 R39 —— 上传专用（只含网站运行文件）

三步：
1) 解压到桌面 → 进到文件夹里面，Ctrl+A 全选，Ctrl+C
2) https://github.com/huatandi/feisu → Add file → Upload files → 粘贴进去 → Commit changes
3) 等 1 分钟，打开 https://huatandi.github.io/feisu/js/core.js
   第一行应是 var VERSION = 'FEISU v5.1.23 · R39';

R39 = P2 倾斜自适应（已用真实条码实证）

做了什么：
1) 角度扫描表补细：0, ±12, ±24, ±36, ±45, 90, ±10, ±20
2) 扫中就把角度记 10 秒 —— 之后同一批货直接按该角度转正再解，
   和"横平"一样快，不再重复找角度。
3) 角度只来自"真的扫中了"，不用猜（详见下方说明）。
4) 连续失败 15 次会把记错的角度丢掉，避免一直转错方向。
5) 诊断新增：
   "angle": { "deg": 0, "hits": 0, "sweeps": 0, "rotated": 0 }
   - deg：当前生效角度（0=横平）
   - hits：靠记忆角度成功命中几次
   - sweeps：角度扫描触发几次
   - rotated：有多少次解码前做了转正

实证结果（用你之前发的 Code 128 条码，人工旋斜后测试）：
   倾斜 15° → 补偿 -10/-20 能读
   倾斜 25° → 补偿 -20/-30 能读
   倾斜 35° → 补偿 -30/-40/-45 能读
   倾斜 45° → 补偿 -40/-45 能读
   倾斜 60° → 需要更高的取样区，暂不支持
即：你要的 15–45° 已覆盖。

一个重要的技术决定（说明为什么不用"自动估角"）：
我先写了一个"梯度估角"版本，实测在真实图上会估错
（20°/30° 都被估成 -47.5°，因为被面板边框和文字干扰），
转正后反而解不出。所以最终采用**确定性扫描**：靠实际解码成功来确定角度，
宁可多花 0.3 秒找角度，也不会瞎转。

耗电：
- 横平时：0 额外开销（角度为 0，根本不走旋转路径）
- 卡住时：每 250ms 试一个角度，最多 2 轮，约 0.3–0.6 秒
- 记住角度后：与横平相同

使用建议：
斜着扫时**保持在取景框中央、别太贴边**（旋转会把条码两端甩出取样区），
第一次会多等约 0.3 秒，后面就连读了。
