FEISU v5.1.24 R40 —— 上传专用（只含网站运行文件）

三步：
1) 解压到桌面 → 进到文件夹里面，Ctrl+A 全选，Ctrl+C
2) https://github.com/huatandi/feisu → Add file → Upload files → 粘贴进去 → Commit changes
3) 等 1 分钟，打开 https://huatandi.github.io/feisu/js/core.js
   第一行应是 var VERSION = 'FEISU v5.1.24 · R40';

R40 修的是“倾斜根本用不了”的真因

R39 的倾斜扫描放在了“恢复路径”里，而那条路有三重门槛：
  - 必须连续失败 850ms 才启动
  - 每次恢复之间还要等 650~3250ms
  - 恢复序列是 decode/quagga/fragment 轮转，平均 3 次才轮到 1 次倾斜
结果：一轮 14 个角度要 20 秒才转完 —— 等于没有。

R40 改成：
- 倾斜扫描搬进主识别循环：连续 4 次解不出，下一次就直接换一个角度再解；
- 每秒约 8 次尝试，一轮 11 个角度约 1.4 秒（原来 20 秒）；
- 扫中后立刻记住该角度 10 秒，之后同一批货直接按该角度转正，和横平一样快；
- 连失 20 次会丢掉记错的角度，重新再来。

实测（用你之前那张 Code 128，按应用完全相同参数：段宽 800、旋转上限 700、双线性）：
   倾斜 15° → 补偿 -10/-20 命中
   倾斜 20° → 补偿 -10/-20/-30 命中
   倾斜 25° → 补偿 -20/-30 命中
   倾斜 30° → 补偿 -20/-30/-40 命中
   倾斜 35° → 补偿 -30/-40/-45 命中
   倾斜 40° → 补偿 -30/-40/-45 命中
   倾斜 45° → 补偿 -40/-45 命中
即 15–45° 全部有解，且不需要你摆正。

验收：
1. 角标 v5.1.24 · 框内识别版 R40
2. 把条码斜 30° 左右放进框中央 → 约 1 秒内应读出（不再要求横平）
3. 紧接着第二件斜着扫 → 应几乎立刻读出（角度已记住）
4. 诊断里 angle.deg 不再是 0（说明记住了斜角），
   angle.sweeps 持续增长（说明在轮角度），angle.hits 说明靠记忆命中几次

注意：斜着扫时把条码放在取景框**中间**，别贴边——旋转会裁掉两端。
60° 以上仍不支持（需要更高的取样区，属于下一步）。
