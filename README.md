# 飞速盘点 Sanfei v4.6.0（快速对焦与实体音效修复版）

## v4.6 真实设备修复

- 把连续对焦、连续曝光和连续白平衡约束直接加入摄像头启动请求，减少预览先模糊、随后才开始聚焦的时间。
- 相机轨道建立后，在约 80ms、320ms、850ms 三次确认连续对焦；只恢复系统连续模式，不执行手动焦距扫动。
- 停止扫描时清理所有对焦确认定时器，不产生后台功耗。
- 新增真实 `scan-success.wav` 与 `scan-error.wav`，使用 HTMLAudio 作为主提示音，Web Audio 合成音降为失败后备。
- 第一次用户触摸扫码按钮时预解锁并预载两个音频，后续识别结果可以直接播放；音频音量固定为媒体通道 100%。

## v4.5 耗电、发热与性能平衡

- 默认以 720p/24fps 启动，足够覆盖常规 EAN/UPC/CODE128，避免每次扫码都让摄像头 ISP 运行在 1080p/30fps 高负载。
- 常规 ZXing 解码间隔自适应调整至约 130ms，降低持续 CPU 占用，同时保持日常条码快速响应。
- 只有持续未识别时才预热和调用 WASM；普通模式至少等待 1.4 秒，增强模式至少等待 0.5 秒。
- WASM 恢复扫描加入 320–500ms 功耗节流；前三秒只处理彩色 ROI，困难条码持续失败后才追加二值化第二遍。
- 持续 2.2 秒仍未识别才把摄像头提升至 1080p 恢复模式，兼顾小条码、远距离条码与日常功耗。
- 扫码成功、手动关闭、切换镜头时清理升频和预热定时器，停止视频轨道及残余解码任务。
- 页面进入后台立即释放摄像头；回到页面后由用户重新点击扫码，避免相机在口袋或切换应用后继续发热耗电。

## v4.4 音效与扫码错误卡片修复

- 扫码成功音提升为更清晰的双频高音，失败音改为更响、更长的低沉提示，并加入动态压缩避免削波失真。
- 页面从后台恢复时自动恢复 AudioContext，降低 iOS/Android/PWA 无声概率；仍保留音效开关与防重复播放。
- “条码不存在”卡片压缩高度，宽度与扫描框左右边缘对齐。
- 卡片自动定位在扫码顶栏下沿与扫描框上沿之间，最大高度随实际空间变化；横竖屏调整时自动重新定位。
- 卡片内部信息、复制和关闭按钮采用紧凑单行布局，长条码自动换行，不遮挡扫描生命线。

## v4.3 网页优先架构

- 获得相机权限后枚举可用镜头；多摄像头设备显示“镜头”切换按钮，并记住选择。
- 选定镜头失效时使用 `ideal` 约束安全回退，不因系统升级或设备变化导致相机打不开。
- 相机启动后后台预热增强解码器，首次困难条码不再临时等待 WASM 初始化。
- 暴露统一 `ScannerAdapter` 边界；未来接入 Capacitor、VisionKit、CameraX/ML Kit 时无需重写盘点业务。

## v4.2 摄像头、解码与列显示升级

- 删除每 300ms 强制扫动手动焦距的逻辑，避免 iPhone/iPad/Android 反复失焦；优先使用系统连续自动对焦。
- 摄像头目标提升至 1080p（设备不支持时自动降级），扫码格式收窄为盘点常用 1D 条码。
- 增加能力检测后的变焦与补光控制；不支持的按钮自动隐藏。
- 增强路径使用完整扫描框 ROI；先保留彩色细节，再尝试二值化，不再只截扫描框下方 45%。
- Android 优先原生 BarcodeDetector；iOS/iPadOS 或能力缺失时按需加载 ZXing-C++ WASM；失败仍回退 ZXing-JS。
- 增强解码加入节流与并发锁，避免连续帧堆积造成卡顿、发热与相机延迟。
- 列管理增加“隐藏/显示”。隐藏只改变屏幕，不删除数据；导出仍保留全部列，并记住隐藏状态。

这是基于 v3.3.38 的“等价拆分 + 稳定性增强”版本，目标是不改变核心操作习惯，同时降低单文件耦合。



## v4.1 新增：扫码双音反馈

- 商品存在：清脆高音“叮” + 极短震动（设备支持时）。
- 商品不存在：低沉“噗/咚” + 双段震动（设备支持时）。
- 摄像头空帧/暂时未识别到条码：**绝不播放失败音**。
- 同一条码短时间重复识别有防抖，避免连续“叮叮叮”。
- 扫码页增加 `🔊 音效 / 🔇 静音` 开关，状态保存在 `localStorage: sanfei_scan_sound_enabled`。
- 使用 Web Audio API 动态合成，不增加 MP3/WAV 文件，继续支持离线。
- iOS/iPadOS 在“开始扫描/确认/Enter”等用户手势中解锁 AudioContext；声音失败不会阻塞扫码。

## 主要增强

- HTML / CSS / JS 拆分，按职责分为 core、storage、search、table、import-export、scanner、columns、keyboard、app。
- 条码精确匹配建立 Map 索引，扫码优先 O(1) 查找；名称/前缀仍保留兼容搜索。
- CSV 改为 PapaParse 直接读取 File + `worker:true` + chunk，避免先 `FileReader.readAsText()` 把整个 CSV 装入内存。
- IndexedDB 自动保存与启动恢复，减少 Safari/PWA 被杀进程后的盘点数据丢失。
- 表格和列管理改为 DOM API 输出，避免导入数据直接拼接 `innerHTML`。
- Ctrl/Cmd + Z 支持最近 100 次单元格修改撤销。
- 删除无效的授权管理运行逻辑（原版已禁用）。
- 扫码代码独立成 scanner.js，并避免重复绑定画面点击对焦事件。

## 部署

直接部署整个目录到 GitHub Pages 即可。仍依赖原有 CDN：SheetJS、PapaParse、ZXing、Tailwind。

## v4.1.3 连续扫码提示优化

新增“条码不存在提示自动接替”机制：

- 条码 A 不存在：显示 `❌ 条码不存在: A`，播放低沉失败音；提示保持，便于操作员查看。
- 相机空帧/未识别到条码：不清除提示，也不播放失败音。
- 镜头反复读到同一个 A：不清除、不闪烁，不产生额外 UI 干扰。
- 随后识别到不同的新条码 B：在处理 B 之前自动清除 A 的不存在提示，无需点击 X。
- B 存在：播放清脆“叮”，显示商品名称并进入原有定位/数量输入流程。
- B 仍不存在：A 提示直接被新的 B 不存在提示替换，并播放 B 的失败音。
- 只自动清理“条码不存在”类扫码提示，不会随意关闭导入失败、系统异常等其他重要提示。

声音系统继续沿用 v4.1.1 的 Web Audio API / iOS AudioContext 解锁方案。


## v4.1.3 条码匹配兼容热修

针对“相机能识别条码，但所有商品都提示条码不存在”增加多层保险：

- 保留 Map O(1) 高速索引。
- 高速索引未命中时，自动回退到 v3.3.38 风格的逐行逐字段 `exactMatch()`。
- UPC-A 12 位与 EAN-13 前导 0 自动等价。
- 增加 GTIN-14 零填充兼容。
- 兼容 CSV/Excel 中常见的引号、空格、制表符及文本数字格式。
- 控制台记录 `[Scanner] decoded`，可看到相机实际识别出的完整条码、格式、长度。
- 搜索失败时记录 `[SearchEngine] no match`、候选值、库存行数、索引键数量。
- “条码不存在”提示显示完整条码。
