# FEISU v5.0.8 · 框内识别版 R14

**当前版本：v5.0.8（R14）** —— 在 v5.0.2 R8 基础上做了 6 件事：

- **取景对齐**：预览画面与蓝色取景框是**同一个矩形**，宽度吃满屏幕（实测占屏 97%），
  高度按摄像头真实比例、竖屏上下留黑；条码离商品约 3cm 起就能完整入框（旧版需要 11cm）。
  解码区域等于框内可见区域（诊断 `view.roiShare` ≈ 100%）。
- **扫码不再跳到别的商品**：摄像头识别**只做精确匹配**（完全相等，或 UPC-A 12 位 ↔ EAN-13 前导 0），
  前缀/包含/片段等近似一律不参与；认不出就报"条码不存在"。残缺码请用「🔢 数字片段」（列候选、人工点选）。
- **连扫计数（可选）**：扫码区点"⚡ 连扫计数"，扫码即 +1、相机不关、不重建整张表，
  底部实时显示"本次 N 件"；再点一次回到"跳行+输入数量"。
- **导出 Excel 的冻结窗格真正生效**（旧版 `ws['!freeze']` 被静默忽略），并且**再导入时保留已盘数量**，可分班续盘。
- **倾斜条码也能读**：主识别恢复 `TRY_HARDER`（多行扫描）。R8 为省电去掉它，导致 ZXing 只扫中间一行，条码一斜就必失败。\n- **不再做无效的整幅补扫**：竖屏轨道下框内只占传感器 31%，旧版仍每 3.5 秒解一次 2MP 整幅（iPhone 上 110ms），现已取消。\n- **摄像头首帧没到时给提示**，不再是一块黑框；并显式重试 `play()`。\n- **扫描线加快到 0.9s/趟**；**提示音再提 4 dB**（压缩峰均比，峰值不变）。\n- **修掉"先窄后撑开/一直撑不开"**：CSS 兜底几何原来写死 80%×220px（比例 1.42），JS 失败时没人纠正；现改为 96% 宽 + min(56.25vw,240px) 高（比例 1.71），并在多处重试布局。\n- **段内宽度上限 800px**：真机 1080 宽段单次 34.5ms，缩小后像素降到 45%、行宽降 26%，桌面实测 8.4→7.5ms 且仍能读出。\n- **提示音加响 +13 dB**：原提示音峰值只有 −14 dBFS（天生就小），已归一化到 −0.3 dBFS。\n- **分段解码**：每次只解框内的一个横向条带（行距从 40px 降到 17px），比 `TRY_HARDER` 便宜 3 倍以上。\n- **提示条不再遮挡顶部对焦说明**。
- 扫描页标题栏在窄屏收成一行，横屏手机也压缩工具条，把高度还给取景。

以下 R4 说明保留作历史记录。


本版修复打开新单按钮不可用，并把换单前的四个选项简化为三个。

- **打开新单**：当前盘点自动保存成功后，直接切换。无需另存文件，也无需再次确认保存。
- **另存备份**：可选，把当前盘点另存为 JSON 文件，包含商品、图片、已盘数量和列设置。操作后仍停留在弹窗，是否换单由你决定。
- **继续当前盘点**：取消换单，继续原来的工作。

自动保存和文件备份用途不同：前者方便随时接着盘点，后者便于另留一份文件。文件分享取消、失败或没有返回，都不会锁住“打开新单”。自动保存失败时保留当前盘点，不切换。

历史最多保留最近保存的50份；达到上限后清理最久未保存的记录，刚保存的旧单可以继续恢复。浏览器网站数据被清除时，浏览器历史也会被删除；需要长期留存的盘点请另存文件。
